## 2. 当前项目现状评估

### 2.1 已有能力（优势）

| 模块 | 现状 | 评价 |
|------|------|------|
| **批量投放** | 支持巨量、OPPO、VIVO、腾讯、华为 5 个平台的程序化批量创建 | 覆盖面广，配置粒度细 |
| **OCPX 转化追踪** | 完整的转化回传平台对接，支持 40+ 媒体平台的回传配置和事件匹配 | 核心壁垒能力 |
| **归因系统** | 独立的事件/属性/归因模型/SDK 配置体系 | 架构设计合理 |
| **ADX 交易** | DSP/RTB 渠道管理、广告计划策略 | 差异化能力 |
| **系统管理** | 完整的多租户 RBAC（用户/角色/菜单/组织/数据范围） | 企业级基础扎实 |
| **素材库** | OSS 存储 + 素材推送 + 文件夹管理 | 基本可用 |

### 2.2 核心不足

| 问题 | 严重程度 | 说明 |
|------|----------|------|
| **无 AI 智能优化能力** | 严重 | 批投创建后无后续自动优化，优化师仍需手动盯盘调整 |
| **无跨平台统一数据分析** | 严重 | 报表按平台分散，无法横向对比各平台投放效率 |
| **素材分析缺失** | 严重 | 只有素材存储和编辑，没有素材投放效果关联分析 |
| **无智能告警系统** | 高 | 无超成本、空耗、异常消耗的实时告警 |
| **无团队协作能力** | 高 | 无审批流、无操作日志回溯、无协作分工 |
| **仪表盘单薄** | 高 | 仅两个基础页面（analytics/workspace），缺乏业务数据的可视化 |
| **无自动化日报/周报** | 中 | 报表订阅仅有基础框架，缺乏自动化生成和推送 |
| **测试覆盖窄** | 中 | 目前仅有巨量和 OPPO 有测试账户，无法验证腾讯/VIVO/华为通道 |

#### 4.1 AI 智能托管引擎

这是与竞品差距最大的模块，也是最高价值的模块。

**核心功能设计：**

```
┌─────────────────────────────────────────────────────────┐
│                    AI 智能托管引擎                        │
├─────────────┬─────────────┬──────────────┬──────────────┤
│  自动止损    │  预算优化    │  出价调整     │  起量追投     │
├─────────────┼─────────────┼──────────────┼──────────────┤
│ • 成本红线   │ • 日预算动态 │ • 基于ROI自动│ • 识别爆量素材 │
│   - 单广告超 │   分配       │   调整出价    │  自动追加预算  │
│   - 账户级超 │ • 优质计划  │ • CPA目标优化│ • 跨账户复制   │
│   - 小时级   │   倾斜预算   │ • 分时段出价  │   爆量素材     │
│   熔断机制   │ • 低效计划  │ • 竞争环境   │ • 素材衰退     │
│ • 异常空耗   │   降预算/关停│   动态响应    │   自动换新     │
│   检测告警   │             │              │               │
├─────────────┴─────────────┴──────────────┴──────────────┤
│  规则配置层：允许用户自定义触发条件、执行动作、生效范围      │
│  执行日志层：每次自动操作的完整记录和回滚能力                │
└─────────────────────────────────────────────────────────┘
```

**技术实现路径：**

1. **API 对接**：利用已有的批投 API 体系，增加广告状态回读和修改接口
2. **规则引擎**：基于时间窗口（小时级）轮询广告效果数据，匹配触发规则
3. **前端配置**：新增 `views/marketing/ai_hosting/` 模块
   - `index.vue` — 托管任务列表（状态：运行中/已暂停/已结束）
   - `create.vue` — 创建托管规则（选择账户范围、触发条件、执行动作）
   - `log.vue` — 操作日志（时间、动作、原因、结果）
4. **触发条件支持**：
   - 成本 > X 元 持续 N 分钟 → 关停
   - 消耗 > X 元且转化 = 0 持续 N 分钟 → 关停
   - ROI < X 持续 N 小时 → 降低出价 Y%
   - ROI > X 且预算未跑满 → 提高出价 Y%
   - 单计划消耗突增 X%（对比前1小时）→ 告警
   - 素材 CTR > X% → 自动追加预算/复制计划

#### 4.2 跨平台统一数据看板

**当前问题**：报表分散在营销模块下，按单平台查看，无法横向对比。

**设计方案：**

新增 `views/dashboard/unified/` 统一数据看板：

```
┌──────────────────────────────────────────────┐
│              统一数据看板 (Dashboard)           │
├──────────┬──────────┬──────────┬─────────────┤
│ 总消耗    │ 总转化    │ 总ROI    │ 总曝光       │
│ ¥XXX     │ XXX      │ X.XX     │ XXX万       │
├──────────┴──────────┴──────────┴─────────────┤
│ 按平台对比          │ 按账户 Top10            │
│ [柱状图: 消耗/ROI]   │ [表格: 消耗/转化/ROI]    │
├─────────────────────┼────────────────────────┤
│ 消耗趋势(折线图)      │ 素材效果排行             │
│ 按天/时/平台拆分      │ CTR/CVR/消耗 Top素材     │
├─────────────────────┼────────────────────────┤
│ 实时消耗监控          │ 异常告警列表             │
│ 今日消耗 vs 昨日同时段  │ 超成本/空耗/异常波动      │
└─────────────────────┴────────────────────────┘
```

**数据来源**：
- 各平台 Report API（已有 `reportApi`、`metricApi`）
- 数据聚合服务：后端定时拉取各平台数据，存入统一数据仓库
- ECharts 图表（现有 OCPX 模块已使用）

#### 4.3 智能告警中心

新增 `views/dashboard/alerts/`：

| 告警类型 | 触发条件 | 通知方式 |
|----------|----------|----------|
| 超成本告警 | 单计划成本 > 目标成本 120% 持续 30min | 站内通知 + 企微/钉钉/邮件 |
| 空耗告警 | 消耗 > 50元 且 转化为 0 持续 1h | 站内通知 |
| 预算撞线 | 消耗达日预算 90% | 站内通知 |
| 素材衰退 | 素材 CTR 连续 3 天下降 > 30% | 站内通知 |
| 账户异常 | 消耗突降 > 50% / 突增 > 100% | 站内通知 |

#### 4.7 AI 投放策略助手

**核心设计**：集成大模型能力，从"工具"升级为"AI 投手"。

```
┌───────────────────────────────────────────────┐
│              AI 投手 (AI Co-Pilot)             │
├───────────────────────────────────────────────┤
│                                                │
│  💬 对话式交互                                  │
│  "帮我把巨量上ROI低于0.8的计划全部关停"            │
│  "今天OPPO的消耗怎么样？有什么异常？"              │
│  "帮我创建10条巨量的应用下载计划，出价30"           │
│                                                │
│  📊 智能诊断                                    │
│  "当前账户存在以下问题：                          │
│    1. 3条计划超成本运行中                        │
│    2. 素材A已衰退3天，建议更换                    │
│    3. 今日消耗同比下降40%，原因：2条主力计划关停"   │
│                                                │
│  🎯 策略推荐                                    │
│  "基于你过去7天的投放数据，建议：                   │
│    1. 将预算向ROI>1.5的计划倾斜20%                │
│    2. 素材B的CTR表现优秀，建议追加5条变体           │
│    3. 凌晨0-6点消耗效率低下，建议设置分时段出价"     │
│                                                │
│  ⚡ 一键执行                                    │
│  "已为您关闭3条超成本计划，预计节省日消耗XXX元"      │
└───────────────────────────────────────────────┘
```

**技术实现**：
1. 将投放数据（消耗、转化、ROI、素材效果）结构化喂给 LLM
2. LLM 生成诊断结论和操作建议
3. 前端渲染为对话气泡 + 可交互的操作卡片
4. 用户可一键执行建议操作（调用批投 API）

### 5.2 核心创新点

#### 创新 1：可编程投放策略（投放 DSL）

让高级优化师用类 SQL/JSON 配置投放策略，而非手动逐个调整：

```json
{
  "strategy": "启动量优先 → ROI 优化",
  "rules": [
    {
      "phase": "cold_start",
      "condition": "消耗 < 200 AND 转化 < 3",
      "action": "出价上调20%，预算不变",
      "max_duration": "2d"
    },
    {
      "phase": "scale_up", 
      "condition": "ROI > 1.2 AND 消耗率 < 80%",
      "action": "预算上调50%，复制爆量素材计划×3"
    },
    {
      "phase": "profit_optimize",
      "condition": "ROI < 0.9",
      "action": "出价下调15%，超成本计划关停"
    }
  ]
}
```

#### 创新 2：投放大盘实时态势感知

不仅仅是自己的数据，还要感知市场环境：

```
实时态势大屏
├── 我的投放实时数据
├── 行业大盘：今日行业平均 CPM / CPC / CTR
├── 竞争热度：当前时段竞品投放密度
├── 流量趋势：各平台当前流量分布
└── 预警信号：CPM 突涨 / 竞争加剧 → 建议调整策略
```

#### 创新 3：素材基因库

将素材标签 + 效果数据构建成可检索的知识库：

```
素材基因库
├── "蓝色背景 + 真人出镜 + 价格锚点" → 平均CTR 3.2%，ROI 1.8
├── "红色背景 + 动画 + 限时优惠" → 平均CTR 2.1%，ROI 1.2
├── 基于基因组合进行素材效果预测
└── AI推荐：你的产品适合 "白色背景 + 产品特写 + 功能对比" 风格
```

#### 创新 4：ADX + DSP 双向联动

利用当前项目已有的 ADX 能力（DSP/RTB 渠道管理），实现：

```
ADX 智能交易
├── 流量采买：通过 RTB/DSP 渠道自动竞价采买流量
├── 投放联调：DSP采买的流量 → 自动创建对应平台的投放计划
├── 效果闭环：投放数据反馈 → 调整 DSP 出价策略
└── 套利监控：DSP成本 vs 投放收入，实时监控利润空间
```

## 6. 当前问题与调整建议

### 6.1 技术架构问题

| 问题 | 建议 |
|------|------|
| **批投模板代码高度重复** | 5 个平台的 `convertToPreviewData.ts` / `index.vue` 核心逻辑大量重复。建议抽象公共层，平台差异通过配置驱动而非代码 fork |
| **枚举文件过大** | `tencent_enums.ts`(1738行)、`bytedance enums.ts`(1175行)、`oppo projectEnum.ts`(1128行)。建议拆分为 JSON 配置文件按需加载，减少打包体积 |
| **缺少数据缓存层** | 每次切换页面都重新请求 API。建议对账户列表、平台配置、素材列表等低频数据做客户端缓存 |
| **TypeScript 类型安全性不足** | 多处使用 `Recordable<any>` 和 `// @ts-ignore`，降低了重构安全性 |

### 6.2 产品设计问题

| 问题 | 建议 |
|------|------|
| **表单复杂度失控** | `platformbehaviora/create.vue`(2000+行) 单文件过大。建议拆分为平台专属配置子组件 |
| **缺少操作指引** | 批投流程对新手不友好，无新手引导、无操作提示。建议增加 Step-by-step 向导模式 |
| **错误提示不友好** | API 错误直接展示后端返回的原始错误信息。建议建立前端错误码映射表，给出可操作的解决建议 |
| **无草稿/撤销功能** | 批投配置复杂，误操作后无法恢复。建议支持自动保存草稿 + 操作历史回溯 |

### 6.3 测试与验证问题

| 问题 | 建议 |
|------|------|
| **仅 2 个平台可测试** | 需尽快获取腾讯广告、VIVO、华为商店的测试账户和 API 权限 |
| **无自动化测试** | 批投逻辑复杂，纯手工测试容易遗漏。建议对 `getRuleInfoCampaignCount` 等核心函数写单元测试 |
| **无沙箱环境** | 测试投放可能产生真实消耗。建议对接各平台的沙箱/测试环境 |

### 6.4 安全性问题

| 问题 | 建议 |
|------|------|
| **密钥硬编码风险** | 各平台 secretKey/appSecret 在前端配置中明文传输。建议所有密钥由后端代理存储，前端只传递引用 ID |
| **操作无审计** | 批投创建/修改没有完整的审计日志。建议每次批投操作记录：操作人、时间、平台、账户、计划数量、配置快照 |
