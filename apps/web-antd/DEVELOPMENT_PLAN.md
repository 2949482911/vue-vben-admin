# 智能投放中台 — 可行性评估与研发计划（Agent 原生架构）

> 基于对前端（apps/web-antd）与后端（~/java/java_object/aegis_m3x_data_analysis/aegis-module-starfiread）的代码级评估
> 目标：**全链路 AI 托管投放**（PRODUCT_DESIGN_V3.md 终极形态）——用户一句话，AI Agent 通过 Tool 自主完成"资产匹配→广告搭建→监测配置→投放→盯盘→优化→汇报"，无需人工干预
> 日期：2026-08-10

---

## 一、可行性结论

**结论：完全可行。现有基础正是"全链路 AI 托管投放"所需的工具原料，缺的是把能力封装为 AI 可调用的 Tool + Agent 运行时骨架。**

关键判断：
1. 本项目的**差异化壁垒（多平台对接、自归因、事件采集、OCPX 回传）已真实落地**——这是 Agent 需要的最难构建的"手脚"
2. 现有能力（批投创建/资产/归因/报表/托管 CRUD）均可**低改造成本封装为 Tool**，供 AI 编排调用
3. 缺口集中在：Agent 运行时（对话→规划→工具→执行→反馈）、统一平台动作适配层、数据同步感知层

**一句话**：手脚已齐（多平台+归因+事件），缺大脑（Agent 编排）和神经（Tool 封装 + 数据感知）。

## 二、Agent 原生架构（架子）

```
┌────────────────────────────────────────────────────────────┐
│  对话层：AI 投放助手（唯一中心入口）                          │
│  意图解析(schema) → 上下文/多轮 → 流式展示                    │
├────────────────────────────────────────────────────────────┤
│  Agent 编排层（核心新建）                                    │
│  任务规划器(Plan) │ Tool 调度器 │ 决策上下文 │ 记忆/审计       │
│  护栏：权限映射 │ 分级审批 │ 金额/频次上限 │ 可撤销             │
├────────────────────────────────────────────────────────────┤
│  工具层（平台无关，现有能力封装为 Tool）                       │
│  Asset  素材/文案/定向/落地页/产品 检索与生成                  │
│  Build  广告参数构建 + 校验                                   │
│  Monitor 监测链接/事件回传配置                               │
│  Control 启停/改价/改预算/复制（统一适配器）                   │
│  Data   报表/素材效果/告警查询                                │
│  Report 投放报告生成                                          │
├────────────────────────────────────────────────────────────┤
│  平台适配层（平台相关）                                       │
│  巨量/智擎/OPPO/腾讯/VIVO/华为：创建/查询/修改 适配器          │
├────────────────────────────────────────────────────────────┤
│  数据层（AI 决策依据）                                        │
│  资产库 │ 效果数据仓库(ad_report_data) │ 归因/事件 │ SelectDB │
└────────────────────────────────────────────────────────────┘
```

**搭架子的三个硬要求**：
1. **Tool 注册中心**：每个 Tool 声明 schema（名称/入参/出参/权限/风险等级），AI 只能调用已注册 Tool，杜绝自由发挥
2. **意图 schema 化**：自然语言 → 结构化 JSON（动作/目标/平台/产品/预算/KPI），动作集收敛
3. **护栏内置**：风险分级（创建=低，改预算=中，关停=高），高敏操作默认人工确认，全程审计可撤销

## 三、现有基础评估（工具原料盘点）

| 能力域 | 前端 | 后端（starfiread） | 是否可直接封装为 Tool |
|--------|------|--------------------|----------------------|
| 广告全链路搭建 | 批投 5 平台+智擎+批量操作 Drawer | advertisement 领域：多平台创建/批量创建/PromotionManager | ✅ 可直接封装（Build/Platform Tool） |
| 账户/资产 | account/asset 多模块 | 账户导入(含小红书)、素材/定向包/标题包/落地页 | ✅ 可直接封装（Asset Tool） |
| 自归因 | ocpx 模块 | attribution：监测链接/归因配置/事件配置 | ✅ 可直接封装（Monitor Tool） |
| 事件采集 | ocpx 事件体系 | event 领域 + 18 平台点击模型 + 行为平台 + 回调 | ✅ 极强（归因/回传闭环已有） |
| 报表/看板 | report + 统一看板 | ReportController 4 接口 | ✅ 部分（Data Tool）；缺 material_rank/alerts |
| 自动化动作 | 托管页面、批量操作 Drawer | **无统一 PlatformApiAdapter**（SDK 原语散落：VIVO 暂停/启停、华为 modify） | ⚠️ 需新建统一适配层 |
| 数据感知 | 统一看板（无数据） | **同步空置**：ReportSchedule 注释、Airflow 空、无 ad_report_data | ❌ 需新建（阶段 3） |
| AI 托管 CRUD | 托管页面 | ai_hosting CRUD 已实现 | ✅ 任务配置可复用，执行引擎需新建 |
| AI 对话/素材分析 | 页面已就绪 | **后端空白**（无 ai_chat/material_analysis/LLM） | ❌ 需新建（阶段 0/4） |

**关键结论**：工具层 70% 已有现成后端能力，搭架子 = ①新建 Agent 运行时 ②把已有能力按 Tool schema 封装 ③补统一动作适配层 + 数据感知。

## 四、技术难点与攻关方案

### 难点 1：Agent 运行时骨架（最大的新工程）
- **难点**：对话→意图→规划→多步工具调用的可靠编排；每步状态可观测、可中断、可回滚
- **攻关**：
  1. 意图 schema 化：动作收敛为固定意图集（create_ad/query_asset/control_ad/set_monitor/generate_report），LLM 只做"填槽"（识别目标/平台/产品/预算/KPI），不自由输出
  2. 任务规划器：用预先定义的**工作流模板**（如"创建广告 = 选素材→选文案→选定向→构建→监测→创建"）而非让 LLM 自由规划，确定性优先；复杂场景才走 Plan-and-Execute
  3. 执行器：每步产生"执行记录"（tool/入参/出参/耗时/状态），前端流式展示；失败自动重试/降级/回滚
  4. 记忆：会话上下文 + 账户偏好 + 历史投放经验（检索注入 Prompt）
- **验收**：多步任务全链路执行成功，中间任意一步可人工打断

### 难点 2：统一平台动作适配层（Control Tool 的地基）
- **难点**：pause/resume/bid/budget/duplicate 在各平台 API 语义不同；幂等与失败处理
- **攻关**：实现 `PlatformApiAdapter` 接口（getAdSnapshot/pauseAd/resumeAd/updateBid/updateBudget/duplicateAd），各平台实现并注册为 Bean（Strategy Map）；操作幂等键防重
- **验收**：一个接口在巨量/OPPO 上都能暂停/调价

### 难点 3：AI 决策可靠性（选素材/选文案/定预算 要有据）
- **难点**：AI"拍脑袋"选素材 → 投放效果差；幻觉导致错误参数
- **攻关**：决策必须查询效果数据（Asset Tool 返回历史 CTR/ROI 排序）；LLM 输出所有数值参数必须过**平台快照校验**（预算在合理区间、出价符合平台规则）；无数据时明确"数据不足，请人工确认"
- **验收**：AI 选择素材时能引用其近 7 天 CTR 作为理由

### 难点 4：数据感知层（AI 盯盘/优化的依据）
- **难点**：各平台 Report API 差异；同步时效（15 分钟级）
- **攻关**：`PlatformReportFetcher` 统一接口 + 后端调度（@Scheduled/XXL-Job），写 ad_report_data；增量 upsert；先巨量/OPPO 可测平台
- **验收**：盯盘 Agent 能读到最新 15 分钟数据并触发动作

## 七、风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| LLM 规划/填槽不可靠 | 高 | 意图 schema + 工作流模板（确定性优先），LLM 只填槽不自由发挥 |
| LLM 幻觉导致错误参数/错误广告 ID | 高 | 执行前平台快照校验 + 风险分级审批 + 可撤销审计 |
| 平台 API 差异导致动作失败 | 中 | 统一适配层 + 幂等键 + 重试退避 |
| 测试账户不足（仅巨量/OPPO） | 中 | 优先可测平台，其余按文档先行待账户联调 |
| 数据同步时效不达标 | 中 | 15 分钟调度 + 失败告警 + 重试 |
